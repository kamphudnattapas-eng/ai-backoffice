# Tax & Control Rules

รายการ Check ทุกข้อที่ระบบรันกับ Document เอกสารนี้เป็นแหล่งความจริงเดียวของกฎ โค้ดใน `taxrules` และ `control` ต้องตรงกับเอกสารนี้ รหัสกฎ (`rule_id`) ใช้ในตาราง `findings`, test และ Golden Set

**ข้อสำคัญ:** กฎภาษีทุกข้อต้องให้ที่ปรึกษาบัญชี (CPA) ยืนยันก่อนเปิดใช้กับลูกค้าจริง กฎที่ยังไม่ยืนยันมีสถานะ `needs-cpa-review` และรันได้เฉพาะใน `local` กับ `staging`

## รูปแบบของกฎ

| คุณสมบัติ | ความหมาย |
| --- | --- |
| `rule_id` | รหัสถาวร เช่น `TAX-001` ห้ามนำรหัสที่เลิกใช้แล้วกลับมาใช้ใหม่ |
| `version` | เพิ่มเมื่อเปลี่ยน logic Finding เดิมเก็บ version ที่ใช้ตอนตรวจไว้ |
| `status` | `draft` → `needs-cpa-review` → `active` → `retired` |
| `applies_to` | Document Type ที่กฎนี้ใช้ |
| `severity` | `critical` (ห้ามส่งออกจนกว่าจะปิด), `warning`, `info` |
| `result` | `pass`, `fail`, `unverified` (ตรวจไม่ได้ในตอนนี้), `skip` (ข้อมูลไม่พอหรือไม่เกี่ยว) |
| `amount_at_risk` | เงินที่อาจเสียถ้าไม่แก้ ใช้ในรายงาน Leakage Scan |
| `effective_from` / `effective_to` | ช่วงวันที่ที่กฎหรือค่าตั้งนี้ใช้ |

ข้อความ `message_th` ของ Finding เขียนตามกฎข้อความใน `docs/GUIDELINES.md` หัวข้อ 6

## กฎด้านภาษี

### TAX-001 รายการครบตามมาตรา 86/4

- **ที่มา:** [มาตรา 86/4 แห่งประมวลรัษฎากร](https://www.rd.go.th/fileadmin/images/image_pramoun/mata86_4_6.pdf)
- **ตรวจ:** ใบกำกับภาษีเต็มรูปต้องมีครบทุกข้อ
  1. คำว่า "ใบกำกับภาษี" ในที่เห็นได้เด่นชัด (`title_text`)
  2. ชื่อ ที่อยู่ และเลขประจำตัวผู้เสียภาษีอากรของผู้ออก (`seller_name`, `seller_address`, `seller_tax_id`)
  3. ชื่อ ที่อยู่ ของผู้ซื้อ (`buyer_name`, `buyer_address`)
  4. หมายเลขลำดับของใบกำกับภาษี และหมายเลขเล่มถ้ามี (`document_no`, `book_no`)
  5. ชื่อ ชนิด ประเภท ปริมาณ และมูลค่าของสินค้าหรือบริการ (`line_items`)
  6. จำนวน VAT แยกจากมูลค่าสินค้าหรือบริการให้ชัดแจ้ง (`subtotal`, `vat_amount`)
  7. วัน เดือน ปี ที่ออก (`issue_date`)
  8. ข้อความอื่นที่อธิบดีกำหนด: ให้ CPA ระบุรายการที่ต้องตรวจเพิ่ม (เช่นเลขผู้เสียภาษีและสาขาของผู้ซื้อ) ก่อนเปิดใช้
- **ผล:** ขาดข้อใดข้อหนึ่ง = `fail` ระดับ critical ถ้าช่องนั้นมี Confidence ต่ำกว่าเกณฑ์ ให้เป็น Review Task ก่อน ไม่ออก Finding ทันที
- **amount_at_risk:** `vat_amount`
- **message_th ตัวอย่าง:** "ใบกำกับภาษีนี้ไม่มีที่อยู่ผู้ซื้อ อาจใช้เคลมภาษีซื้อไม่ได้ ควรขอใบใหม่จากผู้ขาย"

### TAX-002 ผู้ซื้อตรงกับ Client Company

- **ตรวจ:** ถ้ามี `buyer_tax_id` ต้องตรงกับ `client_companies.tax_id` และถ้ามี `buyer_branch` ต้องตรงกับสาขา ชื่อผู้ซื้อหลัง `normalize_thai()` ต้องคล้ายชื่อบริษัท (ตัดคำนำหน้าเช่น "บริษัท", "จำกัด", "(มหาชน)" ก่อนเทียบ)
- **ผล:** เลขผู้เสียภาษีไม่ตรง = `fail` critical, ชื่อไม่คล้ายแต่เลขตรงหรือไม่มีเลข = `fail` warning
- **amount_at_risk:** `vat_amount` เมื่อเป็น critical

### TAX-003 ผู้ขายจด VAT และสาขาตรง

- **ที่มา:** [VAT Service ของกรมสรรพากร](https://www.rd.go.th/42535.html)
- **ตรวจ:** ค้น `seller_tax_id` กับ `seller_branch` ผ่าน `adapters.rd_vat` (มี cache 30 วันใน `vat_registry_cache`)
- **ผล:** ไม่พบว่าจด VAT = `fail` critical, สาขาไม่ตรง = `fail` warning, บริการใช้ไม่ได้ = `unverified` แล้วตรวจซ้ำภายใน 24 ชั่วโมง
- **amount_at_risk:** `vat_amount`

### TAX-004 เลขประจำตัวผู้เสียภาษีถูกรูปแบบ

- **ตรวจ:** 13 หลัก ตัวเลขล้วน และหลักที่ 13 ตรงกับ checksum: คูณหลักที่ 1–12 ด้วย 13, 12, …, 2 ตามลำดับแล้วรวม หลักตรวจสอบ = (11 − (ผลรวม mod 11)) mod 10
- **ผล:** ไม่ผ่าน = `fail` warning และลด Confidence ของช่องนั้นให้ต่ำกว่าเกณฑ์ (มักเป็นความผิดพลาดของ OCR)
- **หมายเหตุ:** ยืนยันสูตรกับเลขของนิติบุคคลจริงอย่างน้อย 50 เลขก่อนเปลี่ยนสถานะ

### TAX-005 ยอด VAT และยอดรวมคำนวณถูก

- **ตรวจ:** `subtotal + vat_amount = total_amount` คลาดได้ไม่เกิน 0.01 บาท และ `vat_amount ≈ subtotal × อัตรา VAT` คลาดได้ไม่เกิน 0.05 บาทต่อรายการสินค้า
- **ค่าตั้ง:** อัตรา VAT เก็บเป็นค่าตั้งที่มี `effective_from` / `effective_to` ใช้ 7% ตามอัตราที่ลดลงและใช้อยู่ ให้ CPA ยืนยันวันสิ้นสุดของมาตรการลดอัตราที่มีผลอยู่
- **ผล:** ไม่ตรง = `fail` warning

### TAX-006 ใบกำกับภาษีอย่างย่อในที่ที่ต้องการใบเต็มรูป

- **ที่มา:** [มาตรา 86/6](https://www.rd.go.th/fileadmin/images/image_pramoun/mata86_4_6.pdf)
- **ตรวจ:** Document เป็น `tax_invoice_abbreviated` และ Client Company จด VAT
- **ผล:** `fail` warning ข้อความบอกว่าใบกำกับภาษีอย่างย่ออาจใช้เคลมภาษีซื้อไม่ได้ ให้ CPA ยืนยันข้อความและกรณียกเว้นก่อนเปิดใช้

### TAX-007 ใบกำกับภาษีเกินช่วงเวลาที่ใช้เคลมได้

- **ตรวจ:** ระยะห่างระหว่าง `issue_date` กับ `tax_period` ที่จะเคลม
- **ค่าตั้ง:** จำนวนเดือนที่ยังเคลมได้ รอ CPA กำหนด (คำถามเปิดข้อ 5 ใน `docs/PRD.md`)
- **ผล:** เกินช่วง = `fail` warning

### TAX-008 แนะนำอัตราภาษีหัก ณ ที่จ่าย

- **ตรวจ:** แยกประเภทเงินได้จาก `line_items` (บริการ, ค่าเช่า, ค่าโฆษณา, ค่าขนส่ง ฯลฯ) แล้วแนะนำอัตรา
- **ค่าตั้ง:** ตารางอัตราตามประเภทเงินได้ให้ CPA กรอกและยืนยัน ค่าที่รู้แล้ว: เมื่อจ่ายผ่านระบบ e-Withholding Tax อัตรา 5%, 3% และ 2% ลดเหลือ 1% ตั้งแต่ 1 ม.ค. 2569 ถึง 31 ธ.ค. 2570 ([ปชส. 14/2569](https://www.rd.go.th/fileadmin/user_upload/news/2569thai/news14_2569.pdf))
- **ผล:** `info` เสมอ เป็นคำแนะนำ ไม่ใช่คำตัดสิน เฟส 2 ใช้ค่านี้ใน S5

### TAX-009 วันที่ในเอกสารสมเหตุสมผล

- **ตรวจ:** `issue_date` ไม่อยู่ในอนาคต, ไม่ก่อนวันที่ผู้ขายเริ่มจด VAT (จาก TAX-003), ไม่ห่างจากวันที่รับเอกสารเกิน 24 เดือน, ปีที่ดูเหมือน พ.ศ. ถูกแปลงแล้ว
- **ผล:** `fail` warning

## กฎด้านการควบคุม

### CTL-001 เอกสารซ้ำ: ผู้ขายและเลขที่เดียวกัน

- **ตรวจ:** ใน Client Company เดียวกัน มี Document อื่นที่ `seller_tax_id` + `seller_branch` + `document_no` (หลัง normalize) ตรงกัน และไฟล์ต่างกัน
- **ผล:** `fail` critical หลักฐานคือลิงก์ไปเอกสารเดิม
- **amount_at_risk:** `total_amount`

### CTL-002 เอกสารซ้ำ: ภาพคล้ายกันมาก

- **ตรวจ:** ในรอบ 12 เดือนของ Client Company เดียวกัน มีหน้าที่ cosine similarity ของ embedding ≥ เกณฑ์ หรือ perceptual hash ต่างกันไม่เกินเกณฑ์ และไฟล์ hash ต่างกัน
- **ค่าตั้ง:** เริ่มที่ cosine ≥ 0.95 และ Hamming distance ≤ 6 แล้วปรับจาก eval
- **ผล:** `fail` warning

### CTL-003 อาจเรียกเก็บซ้ำ

- **ตรวจ:** ผู้ขายเดียวกัน ยอดรวมเท่ากัน เลขที่ต่างกัน ภายใน 7 วัน
- **ผล:** `fail` warning

### CTL-004 ผู้ขายเปลี่ยนเลขบัญชีรับเงิน

- **ตรวจ:** เลขบัญชีในเอกสาร (hash) ไม่อยู่ใน `vendor_bank_accounts` ที่ `verified` ของผู้ขายรายนั้น
- **ผล:** เฟส 1 = `fail` warning, เฟส 2 = `fail` critical และห้ามจ่ายอัตโนมัติจนกว่าจะยืนยันทางโทรศัพท์ (ดู `docs/SECURITY.md`)

### CTL-005 ลายเซ็นหรือตรายางเหมือนกันทุกพิกเซล

- **เหตุผล:** ลายเซ็นจริงของคนเดียวกันต่างกันเล็กน้อยทุกครั้ง ลายเซ็นที่เหมือนกันทุกพิกเซลในเอกสารต่างฉบับมักมาจากการก๊อปวาง
- **ตรวจ:** ตัดภาพลายเซ็นหรือตรายาง สร้าง embedding แล้วหาคู่ที่ cosine ≥ 0.98 หรือ perceptual hash เท่ากัน ข้ามเอกสารต่างฉบับ
- **ผล:** `fail` warning เฟส 1 ใช้เฉพาะใน Leakage Scan

### CTL-006 ใบเสนอราคาคนละผู้ขายแต่หน้าตาเหมือนกัน

- **ตรวจ:** ใบเสนอราคาของงานเดียวกันจากผู้ขายต่างราย มี layout embedding คล้ายกันเกินเกณฑ์ หรือ metadata ของ PDF (ผู้สร้าง, โปรแกรม, เวลาสร้าง) ตรงกัน
- **ผล:** `fail` warning ข้อความเป็นคำแนะนำให้ตรวจสอบ ไม่ใช่ข้อกล่าวหา

## เพิ่มกฎใหม่

1. เพิ่มกฎในเอกสารนี้ด้วยสถานะ `draft` พร้อมที่มา ตรวจอะไร ผล และ amount_at_risk
2. เพิ่มคำตอบของกฎนี้ใน Golden Set อย่างน้อย 20 ตัวอย่างที่ต้อง fail และ 20 ตัวอย่างที่ต้อง pass
3. เขียนโค้ดและ test ตาม `docs/GUIDELINES.md`
4. เปลี่ยนสถานะเป็น `needs-cpa-review` แล้วส่งให้ CPA ยืนยัน
5. CPA ยืนยันแล้วจึงเปลี่ยนเป็น `active` พร้อมบันทึกชื่อผู้ยืนยันและวันที่ใต้กฎ
